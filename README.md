# PC-checker-with-AI

재부팅한 순간부터 PC의 상태를 부품별로 기록하고, 그 기록을 **AI(채팅 또는 API)가 읽고 원인을 판단할 수 있는 형태**로 내보내는 Windows용 진단 도구입니다.

> 상태: **v0.1 (개발 중)** - 1단계 수집 엔진만 동작합니다. 대시보드, 데이터 내보내기, 자동 실행은 아래 로드맵에 있습니다.

## 원칙

- **로컬 전용**: 배포자 서버, 텔레메트리, 원격 설정이 없습니다. 이 도구는 아무것도 자동으로 보내지 않습니다.
- **읽기 전용**: PC의 설정을 바꾸지 않습니다. 의심 장치는 표시만 하고, 끄는 방법은 안내만 합니다.
- **판단은 AI가**: 도구는 수치와 서술형 지표(기울기, 치우침 등)만 만들고 원인을 단정하지 않습니다.
- **추가 설치 없음**: Windows 10 22H2 이상 / Windows 11, 기본 PowerShell 5.1만 씁니다.

## 수집하지 않는 것

**기준**: 기기의 상태와 성능을 설명하는 값만 수집합니다. 사람이나 그 사람이 하는 일의 내용을 알아낼 수 있는 것은 수집하지 않습니다.

수집하지 않는 것:

- 파일과 폴더의 경로·이름, 파일 내용
- 프로그램 실행 시 넘긴 명령줄 인자
- 창 제목, 열어 둔 문서나 탭, 브라우저 기록과 URL
- 키 입력, 클립보드, 화면 캡처, 마이크와 카메라
- 계정 이름, 이메일, 로그인 정보, 비밀번호
- Wi-Fi 이름(SSID)과 비밀번호, IP 주소, MAC 주소
- 메인보드·디스크·BIOS 시리얼 번호
- 설치된 프로그램 전체 목록 (실행 중인 프로세스 이름만 기록)
- 이벤트 로그 본문 중 경로나 계정이 들어간 부분 (마스킹 후 저장)
- 위치, 연락처

수집하는 것:

- CPU(코어별), GPU, 메모리, 디스크, 네트워크 어댑터의 사용량·지연·처리량
- 온도, 팬, 클럭, 전력 같은 센서 값 (읽을 수 있는 경우)
- 하드웨어 모델명, 드라이버 버전, OS 빌드
- 실행 중인 **프로세스 이름**, 시작·종료 시각, 최대 CPU·메모리 사용량, 실행 파일의 제조사명·파일 설명
- 사용자가 직접 남긴 구간·메모 마커의 라벨

컴퓨터 이름과 사용자 이름은 저장 전에 `<PC>`, `<USER>`로 바꿉니다.
알려진 한계: 사용자 이름이 흔한 단어(예: `User`)이면 프로세스 설명 속 같은 단어까지 `<USER>`로 바뀔 수 있습니다. 개인정보 쪽으로 치우친 동작입니다.

## 사용법 (현재)

```powershell
# 수집 시작 (Ctrl+C 로 중지)
powershell -ExecutionPolicy Bypass -File .\src\Start-Collector.ps1

# AI가 "OO 프로그램을 켜 보세요"라고 했을 때: 시작 - 끝으로 감싸기
.\src\Mark.ps1 start "OBS 켬"
.\src\Mark.ps1 end

# 증상이 나타난 순간 (이후 5분간 촘촘히 기록)
.\src\Mark.ps1 note "화면 잘림"
```

데이터는 `%LOCALAPPDATA%\PCCheckerWithAI\data`에 저장됩니다. 라벨에는 개인정보를 쓰지 마세요.

### 측정 계획 (부팅 후 경과 시간)

| 구간 | 간격 | 설명 |
| --- | --- | --- |
| 0~5분 | 촘촘히 | 부팅 직후 안정화 |
| 5~30분 | 5초 | 기준선. 이 시간엔 PC를 평소처럼 두세요 |
| 30분~ | 5초 | 일반 |
| 구간 마커가 열린 동안, 메모 후 5분 | 촘촘히 | 증상 재현 구간 |

CIM 성능 클래스를 한 번 읽는 데 약 1.5초가 걸려서, '촘촘히'의 실제 간격은 2~3초입니다.

### 저장 구조

```
boot_<부팅시각>\meta.json         하드웨어 모델/수집 설정
boot_<부팅시각>\raw_*.jsonl       틱 원본 (24시간 보관)
boot_<부팅시각>\minute.jsonl      1분 평균/최대/상위5% (30일 보관)
boot_<부팅시각>\processes.jsonl   프로세스 이름·시작/종료·최대 사용량
boot_<부팅시각>\markers.jsonl     구간/메모 마커
```

## 알려진 한계

- **CPU 온도·케이스 팬 RPM**은 Windows 기본 기능으로 읽을 수 없습니다. LibreHardwareMonitor 또는 OpenHardwareMonitor가 켜져 있으면 그 값을 읽고, 없으면 "측정 불가"로 표시합니다.
- GPU 온도·팬·스로틀 사유는 NVIDIA(`nvidia-smi`)에서만 읽습니다. 사용률은 제조사 공통입니다.
- 코어별 사용률과 프로세스 CPU는 부스트 때문에 100을 넘을 수 있습니다 (프로세스 값은 '코어 1개 기준 %').
- 개발자의 PC(NVIDIA 그래픽, 데스크톱 1대)에서만 실제 검증했습니다. AMD/Intel 그래픽, 노트북 배터리, 센서 프로그램이 켜진 상태는 코드 검토와 모의 데이터로만 확인합니다.

## 로드맵

1. ✅ 수집 엔진: 단계별 샘플링, 구간 마커, 프로세스 기록, 압축·보관
2. 데이터 파일: 와이드 CSV, `schema.md`, `summary.json`, 원인 후보 체크리스트
3. 히트맵 HTML 대시보드 (절대/상대 색 기준 전환, 팬 통합 열, 이상 순 정렬)
4. 가벼운 AI용 팩: `summary.md`(글자 히트맵 포함), PNG 그래프, `charts_guide.md`
5. 로그온 자동 실행, 제거 스크립트, 마커 패널
6. (선택) 사용자가 API 키 또는 로컬 AI 주소를 넣었을 때만 "AI에게 보내기"
