# PC-checker-with-AI

재부팅한 순간부터 PC의 상태를 부품별로 기록하고, 그 기록을 **AI(채팅 또는 API)가 읽고 원인을 판단할 수 있는 형태**로 내보내는 Windows용 진단 도구입니다.

> 상태: **v0.6 (개발 중)** - 수집 엔진, 데이터 내보내기, 히트맵·꺾은선 대시보드, 가벼운 AI용 팩, 로그온 자동 실행(트레이·표시하기 창), AI 자료 요청 명령 모음이 동작합니다.

## 원칙

- **로컬 전용**: 배포자 서버, 텔레메트리, 원격 설정이 없습니다. 이 도구는 아무것도 자동으로 보내지 않습니다.
- **읽기 전용**: PC의 설정을 바꾸지 않습니다. 의심 장치는 표시만 하고, 끄는 방법은 안내만 합니다.
- **판단은 AI가**: 도구는 수치와 서술형 지표(기울기, 치우침 등)만 만들고 원인을 단정하지 않습니다.
- **추가 설치 없음**: Windows 10 22H2 이상 / Windows 11, 기본 PowerShell 5.1만 씁니다.

## 데이터와 개인정보

**한눈에 보기**

1. 이 도구가 만드는 데이터는 **모두 이 PC 안**(`%LOCALAPPDATA%\PCCheckerWithAI`)에만 저장됩니다. (선택 기능인 자동 실행을 설치하면 아래 표의 마지막 줄처럼 시스템에 설정이 몇 개 더 남습니다.)
2. 이 도구에는 **데이터를 밖으로 보내는 기능이 없습니다.** 서버, 텔레메트리, 자동 업로드, 원격 설정이 모두 없습니다.
3. 데이터가 PC 밖으로 나가는 때는 **사용자가 직접 복사해서 붙여 넣거나 파일을 첨부할 때뿐**입니다. 그때 나가는 내용은 아래 "1)" 표의 "내보내기 결과"와 같으니, 공유하기 전에 파일을 열어 확인하세요.

### 2) 밖으로 나갈 수 있나요?

| 경로 | 나가는 것 | 언제 |
| --- | --- | --- |
| 이 도구가 스스로 | **없음**. 코드에 웹 요청이 없고, 테스트가 이를 정적으로 점검합니다 | - |
| 네트워크 사용 | `Probe.ps1 network`가 **같은 공유기(내부망)에 핑 10번**을 보냅니다. 외부 인터넷으로는 나가지 않습니다 | 사용자가 그 명령을 실행했을 때만 |
| 대시보드 파일 | 없음. 외부 폰트·스크립트·이미지가 없어서 열어도 인터넷에 접속하지 않습니다 (테스트가 점검) | - |

| "AI에게 보내기"(예정) | 아직 구현되지 않았습니다. 만든다면 기본으로 꺼 두고, 사용자가 키나 주소를 직접 넣었을 때만 동작하게 합니다 | - |

공유하기 전에 `summary.md`·`summary.json`을 열어 보세요. **프로세스 이름과 하드웨어 모델명은 들어 있습니다.**

### 3) 읽지 않는 것

- 파일과 폴더의 경로·이름·내용, 프로그램 실행 시 넘긴 명령줄 인자
- 창 제목, 열어 둔 문서나 탭, 브라우저 기록과 URL
- 키 입력, 화면 캡처, 마이크와 카메라 (클립보드는 읽지 않고, 복사 버튼은 쓰기만 합니다)
- 계정 이름, 이메일, 로그인 정보, 비밀번호
- Wi-Fi 이름(SSID)과 비밀번호, 메인보드·디스크·BIOS 시리얼 번호
- 설치된 프로그램 전체 목록 (실행 중인 프로세스 이름만 기록)
- 위치, 연락처

### 4) 가리기(마스킹) 방식과 한계

- 이벤트 메시지나 마커 라벨 같은 **자유 텍스트**는 저장하기 전에 컴퓨터·사용자 이름을 `<PC>`·`<USER>`로, 파일·장치 경로를 `<경로>`로, 이메일·IP·MAC을 `<EMAIL>`·`<IP>`·`<MAC>`으로 바꿉니다.
- 프로세스 이름, 제조사·파일 설명, 드라이버 버전, 하드웨어 모델명은 값 자체가 정보라서 가리지 않습니다.
- 한계: 사용자 이름이 흔한 단어(예: `User`)이면 이벤트 메시지 속 같은 단어까지 `<USER>`로 바뀔 수 있습니다. 개인정보 쪽으로 치우친 동작입니다.
- 사용자가 직접 실행하는 확인 명령(`Probe.ps1`, 아래 "AI에게 추가 자료 요청하기")의 출력에는 시작 프로그램 이름, 서비스 이름, 드라이버 이름·버전, 이벤트 요약이 들어갈 수 있습니다. 자동 수집이 아니라 사용자가 화면에서 확인한 뒤 붙여 넣는 글입니다.

### 5) 지우는 법

- 기록과 결과를 모두: 자동 실행을 설치했다면 `Uninstall-AutoStart.ps1 -RemoveData`, 아니면 `%LOCALAPPDATA%\PCCheckerWithAI` 폴더를 삭제합니다.
- 자동 실행만 제거(데이터는 남김): `Uninstall-AutoStart.ps1`
- 내보낸 결과만: `data\export` 폴더를 삭제합니다.
- 대시보드의 브라우저 저장값: 브라우저의 사이트 데이터를 삭제합니다.

## 사용법 (현재)

```powershell
# 수집 시작 (Ctrl+C 로 중지)
powershell -ExecutionPolicy Bypass -File .\src\Start-Collector.ps1

# AI가 "OO 프로그램을 켜 보세요"라고 했을 때: 시작 - 끝으로 감싸기
.\src\Mark.ps1 start "OBS 켬"
.\src\Mark.ps1 end

# 증상이 나타난 순간 (이후 5분간 촘촘히 기록)
.\src\Mark.ps1 note "화면 잘림"
```

데이터는 `%LOCALAPPDATA%\PCCheckerWithAI\data`에 저장됩니다. 라벨에는 개인정보를 쓰지 마세요.

### 내보내기 (AI에 넘길 파일 만들기)

```powershell
# 가장 최근 부팅의 기록을 파일로 (기본: 최근 72시간 분석, 부팅 이후 이벤트 포함)
powershell -ExecutionPolicy Bypass -File .\src\Export-Data.ps1
```

`%LOCALAPPDATA%\PCCheckerWithAI\data\export\boot_...\` 에 4개 파일이 만들어집니다.

| 파일 | 내용 |
| --- | --- |
| `metrics_1min.csv` | 분 단위 와이드 표(행=1분, 열=지표). 팬은 개별 열 옆에 통합 열(`fan_group.*`) |
| `processes.csv` | 프로세스 이름별 요약 (경로·인자·창 제목 없음) |
| `summary.json` | 지표별 요약(기울기, 치우침, 튀는 순간, 식는 속도), 구간·메모 전후 비교, 시스템 스냅샷, **원인 후보 체크리스트** |
| `schema.md` | 열 이름·단위·설명·임시 기준 |

도구는 원인을 단정하지 않습니다. 원인 후보는 `supports`(임시 기준 이상으로 관측) / `against`(측정했고 기준 미만) / `no_data`(수집 안 됨) 중 하나만 표시하고, 모든 기준값은 임시(provisional)입니다.

### 대시보드 (사람이 보는 화면)

```powershell
# 내보낸 파일을 인터넷 없이 열리는 HTML 하나로 묶고 브라우저로 엽니다
powershell -ExecutionPolicy Bypass -File .\src\Build-Dashboard.ps1 -Open
```

`export\boot_...\dashboard.html`이 만들어집니다. 데이터가 파일 안에 들어 있어서 더블클릭만 해도 열리고, 외부 폰트·스크립트·이미지를 쓰지 않습니다.

- **꺾은선 보기**: 그룹마다 **히트맵 / 꺾은선**을 전환할 수 있습니다(온도·팬 그룹은 두 선의 관계를 보는 게 핵심이라 꺾은선이 기본). 단위가 같은 줄끼리 한 그래프에 모이고(°C와 %는 같은 0~100 눈금), 이름표를 눌러 줄을 켜고 끌 수 있으며 선택은 기억됩니다. 마우스나 방향키로 시각을 옮기면 십자선과 값이 나옵니다. 색만으로 구분하지 않도록 **선 모양(실선·파선·점선·쇄선)** 과 줄 끝 이름을 같이 쓰고, 임시 기준선·내가 표시한 구간·증상 메모도 함께 그립니다. 외부 라이브러리 없이 SVG로 직접 그립니다.
- **히트맵**: 가로는 시간, 세로는 부품(CPU, 메모리, 디스크, 네트워크, GPU, 온도·팬, 프로세스). 색 기준은 **절대(임시 기준)** 와 **상대(그 줄의 최소~최대)** 를 전환하고, 칸의 값은 **평균 / 가장 높았던 순간**, 줄 순서는 **기본 / 이상한 순**으로 바꿀 수 있습니다.
- **색만으로 구분하지 않습니다**: 점무늬(주의)·빗금(높음) 질감, 줄 끝의 평균·최고 숫자와 `정상/주의/높음` 글자 칩, 칸마다 값 툴팁(마우스·방향키), 숫자 그대로 보는 "표로 보기"를 함께 둡니다.
- **팬**: 센서 프로그램이 있으면 팬 개별 줄 바로 아래에 종류별 통합 줄(케이스·CPU·GPU)이 굵게 붙습니다. 없으면 "측정 불가"와 켜는 방법을 안내합니다.
- **구간·메모**: 내가 표시한 구간은 띠로, 증상 메모는 ◆로 표시하고 전후 비교를 보여줍니다.
- **원인 후보 체크리스트**: `근거 있음 / 근거 없음 / 데이터 없음`만 표시합니다(결론 없음).
- **AI에게 보여줄 내용 복사**: 요약 텍스트를 클립보드에 복사합니다. 어디로도 전송하지 않습니다. 더 자세한 분석에는 `metrics_1min.csv`·`summary.json`·`schema.md`를 함께 첨부하세요.
- 라이트/다크(OS 설정 따름, 수동 전환), 모바일 폭 지원.

| `chart_3_thermal_fan.png` | 온도와 팬 속도, "온도는 낮은데 팬은 높은" 구간 음영 (온도 센서가 있을 때) |
| `chart_4_cpu_gpu.png` | CPU·GPU·영상 디코드 사용률 |
| `chart_5_memory_disk.png` | 메모리 약속량·남은 메모리·디스크 사용 시간·응답 시간 |
| `chart_6_segments.png` | 표시한 구간·메모 전후 변화 (구간·메모가 있을 때) |
| `charts_guide.md` | 각 그림이 무엇이고 어떻게 읽는지 |

- 그림은 코드로 그린 PNG(폭 1000px 이하, 장당 300KB 이하)이고, **각 그림 아래에 읽는 법 설명 띠**가 붙어 있어 그림만 따로 받아도 뜻을 알 수 있습니다.
- 색만으로 구분하지 않습니다: 점·빗금 무늬, 실선·파선·점선·쇄선, 줄 끝 이름 표시, 숫자를 함께 씁니다.
- 모든 기준선과 정상/주의/높음 표시는 **임시 값**이라고 그림과 문서에 적습니다. 데이터가 없는 그림은 만들지 않고(예: 센서가 없으면 CPU 온도 선 없음), 빠진 그림은 "측정되지 않았다"는 뜻이지 "문제가 없다"는 뜻이 아닙니다.
- 낮을수록 나쁜 지표(남은 메모리)는 하위 5% 값으로, 높을수록 나쁜 지표는 상위 5% 값으로 판정합니다.

### AI에게 추가 자료 요청하기 (명령 모음)

AI와 분석하다 보면 새 자료가 필요해집니다. 그때 AI가 아무 명령이나 지어내지 않도록, **미리 정해 둔 요청 목록**을 만들어 두었습니다. `summary.md`(가벼운 팩), `summary.json`의 `ai_protocol`·`data_requests`, 대시보드의 "AI에게 더 줄 자료", "AI에게 보여줄 내용 복사" 문구에 같은 규칙과 목록이 들어 있습니다.

**AI가 따르는 규칙**: 목록의 번호(R1~R12, S1~S4)와 그 명령만 요청하고, 목록에 없는 정보는 명령을 만들지 말고 말로 설명한다. 한 번에 최대 3개까지, 요청마다 "무엇을 확인하려는지" 한 줄을 적는다. 개인정보는 요구하지 않는다.

| 번호 | 명령 (`powershell -ExecutionPolicy Bypass -File .\src\Probe.ps1 <이름>`) | 용도 |
| --- | --- | --- |
| R1 | `display` | 화면 잘림·해상도·배율·가상 디스플레이 |
| R2 | `gpu` | GPU 온도·팬·클럭·성능 제한 사유 (NVIDIA) |
| R3 | `drivers` | 드라이버 버전, 문제가 보고된 장치 |
| R4 | `startup` | 시작 프로그램·멈춰 있는 서비스 이름 |
| R5 | `events -Hours 24` | 최근 N시간 경고·오류 이벤트(경로·계정 가림) |
| R6 | `power` | 전원 계획, 빠른 시작, 배터리 |
| R7 | `disks` | 디스크 상태, 드라이브 여유 공간 |
| R8 | `memory -Top 10` | 메모리 현황, 메모리 쓰는 프로그램 |
| R9 | `processes -Top 10` | 지금 CPU·메모리를 쓰는 프로그램(이름별 합산) |
| R10 | `network` | 연결된 어댑터, 공유기까지의 응답 시간·손실 (외부 인터넷으로는 보내지 않음) |
| R11 | `sensors` | 센서 프로그램이 켜져 있는지, 온도·팬 센서 값 |
| R12 | `boot` | 부팅 시각, 최근 30일 비정상 종료·재부팅 |
| S1~S4 | `Mark.ps1` / `Make-Report.ps1` | 증상 재현 구간 기록, 순간 메모, 센서 켜고 재기록, 새 리포트 |

- 모든 R 명령은 **읽기 전용**이고 결과는 **약 4KB 이내의 짧은 글**입니다. `-Copy`를 붙이면 클립보드에도 복사되고, `Probe.ps1 list`로 목록을 볼 수 있습니다.
- 결과 글은 사용자가 그대로 AI에게 붙여 넣습니다. 도구는 아무것도 자동으로 보내지 않습니다.
- 출력에서는 계정·컴퓨터 이름·사용자 폴더 경로·이메일·IP·MAC을 가리고, 이벤트 본문의 파일·장치 경로는 통째로 지웁니다. 시리얼 번호·Wi-Fi 이름·명령줄·창 제목은 읽지 않습니다.
- 목록은 `src\RequestCatalog.ps1` 한 곳에서 관리하므로 항목을 추가하면 모든 곳에 같이 반영됩니다.

### 로그온 시 자동 실행 (선택)

재부팅할 때마다 직접 켜지 않아도 기록이 시작되게 합니다. **이 PC에 남는 설정을 만들기 때문에 무엇을 만드는지 먼저 보여주고 확인을 받습니다.**

```powershell
# 1) 미리보기: 무엇을 만들지만 보여주고 아무것도 바꾸지 않습니다
powershell -ExecutionPolicy Bypass -File .\src\Install-AutoStart.ps1 -WhatIf

# 2) 설치 (확인 질문 후 진행). -DesktopShortcut 을 주면 바탕화면에 '표시하기' 바로가기도 만듭니다
powershell -ExecutionPolicy Bypass -File .\src\Install-AutoStart.ps1 -DesktopShortcut -StartNow

# 3) 되돌리기: 만든 것을 모두 지웁니다. 기록한 데이터는 -RemoveData 를 줘야만 지웁니다
powershell -ExecutionPolicy Bypass -File .\src\Uninstall-AutoStart.ps1 -WhatIf
powershell -ExecutionPolicy Bypass -File .\src\Uninstall-AutoStart.ps1
```

만드는 것 (모두 현재 사용자 권한, **관리자 권한 불필요**, 외부 전송 없음):

| 무엇 | 어디에 |
| --- | --- |
| 스크립트 복사본 (저장소 폴더를 옮겨도 계속 동작) | `%LOCALAPPDATA%\PCCheckerWithAI\app\src` |
| 로그온 30초 뒤 실행되는 작업 스케줄러 작업 `PCCheckerWithAI-Logon` (숨김, 시간 제한 없음, 배터리에서도 실행) | 작업 스케줄러. 등록이 거부되면 **시작 폴더 바로가기**로 대신합니다 |
| (선택) 바탕화면 바로가기 "표시하기" | 바탕화면 |

로그온하면 수집기와 **트레이 아이콘**이 함께 시작됩니다.

- **트레이 아이콘**(알림 영역): 왼쪽 클릭은 "표시하기" 창, 오른쪽 클릭은 메뉴입니다. 메뉴에서 **대시보드 열기**, **AI에 줄 가벼운 파일 만들기**, 기록 켜기/끄기, 시작 알림 켜고 끄기를 할 수 있습니다. 부팅 후 **처음 한 번만** 작은 알림을 띄우고(메뉴에서 끌 수 있음), 그 뒤로는 조용히 상태만 툴팁에 보여줍니다.
- **"표시하기" 창**: 이름 한 줄을 적고 **구간 시작 / 구간 끝 / 증상 메모** 버튼을 누르면 `Mark.ps1`과 같은 일을 합니다. 현재 기록 상태(● 기록 중 / ▲ 갱신 안 됨 / ■ 멈춤)와 열린 구간 이름이 보이고, "대시보드 열기"와 "AI용 가벼운 파일" 버튼으로 한 번에 리포트를 만듭니다.
- 한 번에 리포트: `.\src\Make-Report.ps1 [-Pack full|light] [-Open dashboard|folder|none]` (내보내기 → 대시보드 → 선택적으로 가벼운 팩)

알려진 한계: 로그온 때 PowerShell 창이 아주 잠깐 깜빡일 수 있습니다(숨김 창으로 시작하기 전). 코드 서명이 없어서 보안 프로그램이 스크립트를 경고할 수 있습니다.

## 알려진 한계

- **CPU 온도·케이스 팬 RPM**은 Windows 기본 기능으로 읽을 수 없습니다. LibreHardwareMonitor 또는 OpenHardwareMonitor가 켜져 있으면 그 값을 읽고, 없으면 "측정 불가"로 표시합니다.
- GPU 온도·팬·스로틀 사유는 NVIDIA(`nvidia-smi`)에서만 읽습니다. 사용률은 제조사 공통입니다.
- 코어별 사용률과 프로세스 CPU는 부스트 때문에 100을 넘을 수 있습니다 (프로세스 값은 '코어 1개 기준 %').
- **측정 자체의 부하**: 성능 카운터를 주기적으로 조회하므로 `WmiPrvSE`·`powershell`의 CPU 사용이 실제보다 높게 보일 수 있습니다. `collector.cpu_core_pct`가 수집기 자신의 사용률, `collector.wmi_host_cpu_core_pct`가 WMI 제공자의 합계입니다. 개발 PC(논리 코어 28개, 5초 간격)에서 측정한 값은 수집기 약 3.6% + WMI 제공자 약 18% (코어 1개 기준)였습니다.
- 1분 평균 기반이라 1분 미만의 짧은 순간 현상은 평균에 묻힙니다(`__max` 열과 `max_peak_in_any_minute` 참고). 구간·메모 비교는 24시간 보관되는 원본 틱을 씁니다.
- 관리자 권한이 없으면 디스크 마모/오류 카운터(SMART)는 수집되지 않습니다.
- 개발자의 PC(NVIDIA 그래픽, 데스크톱 1대)에서만 실제 검증했습니다. AMD/Intel 그래픽, 노트북 배터리, 센서 프로그램이 켜진 상태는 코드 검토와 모의 데이터로만 확인합니다.
