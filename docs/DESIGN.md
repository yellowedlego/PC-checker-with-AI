# 설계 결정 기록

개발 초기에 정한 결정을 모아 둡니다. 구현이 바뀌면 이 문서도 같이 고칩니다.

## 목적

- 증상(예: 화면 잘림과 영상 끊김, 온도가 내려가도 계속 큰 팬 소리)을 AI가 다각도로 분석할 수 있게, 재부팅 직후부터의 통계를 만든다.
- 배포용 범용 도구다. 특정 PC에 의존하지 않는다.

## 결정

| 주제 | 결정 |
| --- | --- |
| 배포 형태 | PowerShell 수집기 + 데이터가 들어 있는 HTML 대시보드(zip). 추가 설치 없음 |
| 중앙 통제 | 없음. 서버, 텔레메트리, 자동 전송 없음 |
| 측정 계획 | 부팅 후 0~5분 촘촘히, 5~30분 기준선, 이후 일반. 구간/메모 마커로 증상 재현 구간을 감쌈 |
| 부하 테스트 | 기본 제외 (수동 관찰만) |
| 센서 | 설치/드라이버 번들 없음. 센서 프로그램이 켜져 있으면 읽고, 없으면 "측정 불가" |
| GPU | 사용률은 제조사 공통 카운터, NVIDIA는 온도·팬·스로틀 보강 |
| 보관 | 원본 24시간, 1분 요약(평균·최대·상위5%) 30일 |
| 프로세스 | 이름·시각·최대 사용량·제조사/설명만. 경로·인자·창 제목 없음 |
| 마스킹 | 컴퓨터/사용자 이름, 경로, 이메일, IP, MAC은 저장 전에 치환 |
| 시각화 | 숫자 나열 대신 히트맵. 절대 기준/상대(최소~최대) 기준 전환, 팬은 개별 열 + 통합 열 |
| AI 파일 | 와이드 CSV + `schema.md` + `summary.json`, 가벼운 AI용 팩(글자 히트맵, PNG, 그래프 설명) |
| 서술 지표 | 기울기, 치우침, 튀는 순간, 식는 속도. 원인 판단은 하지 않고, 정상 범위 표시는 '임시 기준'임을 명시 |
| 원인 후보 | 분야별 체크리스트에 "근거 있음/없음/데이터 없음"만 표시, 결론 없음 |
| 의심 장치 | 표시만 하고 설정은 바꾸지 않음 |
| API | 사용자가 키 또는 로컬 AI 주소를 넣었을 때만 보내기 버튼 노출, 키는 DPAPI로 암호화 저장 |
| 자동 실행 | 로그온 시 작업 스케줄러 등록 (관리자 권한 없이), 제거 스크립트 제공 |
| 지원 범위 | Windows 10 22H2+/11, PowerShell 5.1, 한국어 기본(문구 분리), MIT |

## 디자인 방향 (3단계 대시보드에 적용)

- 통일되고, 눈이 편안하고, 친근하게. 따뜻한 중성 배경, 낮은 채도의 색, 넉넉한 여백, 부드러운 모서리.
- 초보자가 한눈에 읽을 수 있어야 하고, 같은 데이터를 AI는 파일로 읽는다.
- 히트맵 색은 색약에서도 구분되는 팔레트를 쓰고, 색 외에 숫자·기호로도 상태를 알 수 있게 한다.

## 작업 규칙

- 개인정보가 저장소에 들어가지 않게 한다 (수집 데이터·보고서·로그는 `.gitignore`).
- 다양한 방향을 시도할 때는 반드시 브랜치를 만든다.
- 푸시는 내용을 보여 준 뒤 확인을 받고 한다.
